## 9.1 `BootstrapAdminInitializer` —— 启动时补组织和平台管理员

**源码**：[BootstrapAdminInitializer.java](../backend-java/orbit-academic/src/main/java/com/orbit/academic/config/BootstrapAdminInitializer.java)

**谁调它**：Spring Boot 启动时执行 `ApplicationRunner.run()`；下游直接用 `JdbcTemplate` 访问组织和用户表，用注入的 `PasswordEncoder` 编码密码。

### 构造器

保存 JDBC、密码编码器及两个配置值：`ORBIT_ADMIN_USERNAME` 默认 `admin`，`ORBIT_ADMIN_PASSWORD` 默认 `Admin@123`。配置在构造时解析；这里只保存值，不立即建账号。

### `public void run(ApplicationArguments args)`

1. 调 `firstOrganizationId()` 取 id 最小的组织；不存在就先创建“默认学校”。这一步发生在用户计数之前。
2. 全库统计 `users`，不是只统计刚选定的组织。
3. 没有用户时插入一个账号：组织为上一步结果，角色 `platform_admin`，启用，`must_change_password=true`，时间取 `UtcTimes.now()`。密码先编码再入库，随后直接返回。
4. 已有用户时统计全库平台管理员；只要已有一个，就结束。
5. 没有平台管理员时，只在第一个组织里找 id 最小的 `admin`，存在就把其角色提升为 `platform_admin`；找不到则不做任何处理。

`@Transactional` 让本次组织插入、用户插入或角色更新处于同一事务；后续 SQL 失败会回滚本次事务。

> ⚠ “已有用户不覆盖账号或密码”不等于“已有用户完全不变”：这里可能更新已有管理员的角色。其他组织有管理员，也不会替代第一个组织参与查找。
>
> ⚠ 代码使用“先计数再插入”，没有显式锁或多实例协调；不能把单次事务解释成并发首次启动绝不会竞争。

### `private Long firstOrganizationId()`

`ORDER BY id LIMIT 1` 得到稳定的首个组织。查询返回列表，空列表转 `null`，否则取 `getFirst()`；不会因为没有组织而直接触发单行查询异常。

### `private long createDefaultOrganization()`

创建 `GeneratedKeyHolder` → 用支持 `RETURN_GENERATED_KEYS` 的 `PreparedStatement` 插入名称与 UTC 时间 → 从返回键取组织 id。时间先转成 JDBC `Timestamp`；没有通过“再查询最大 id”猜测本次插入记录。

## 9.3 `ScoreService` —— 独立统计质量并保存评分快照

**源码**：[ScoreService.java](../backend-java/orbit-scheduling/src/main/java/com/orbit/scheduling/score/ScoreService.java)

**谁调它**：`ScoreController`；下游是版本及条目 Mapper、academic 表的只读 Mapper、`RuleSetService`、`VersionValidator` 和 Jackson 2 `ObjectMapper`。

构造器只保存这些依赖，不执行评分。评分没有复用 CP-SAT 的目标值，而是重新统计实际课表。

### `public ScoreResponse score(long organizationId, long versionId)`

1. `requireVersion()` 同时按组织与版本查询；无规则指纹则抛 409“该课表版本没有规则集指纹，无法生成可追溯评分”。
2. `loadModel()` 加载版本条目和当前组织主数据；`rulesByHash()` 加载版本指纹对应的规则，避免直接使用当前编辑中的规则集。
3. `hardViolations()` 先做基础合法性检查。
4. 逐条规则调用 `measure()`，计算满足百分比，形成 `RuleMetric`。软规则累加“百分比 × 权重”及总权重，同时累计原始违规/机会；硬规则只要有违规，就把说明加入硬错误列表。
5. 软规则折合 50 分；再独立计算教师空档 20 分、分布均衡 15 分、主科上午 15 分。这三项即使规则集中没有对应软规则也照算。
6. 生成四个维度。软规则维度的原始违规总数用于展示；其得分来自逐条规则加权，不能直接拿原始总数之比还原。
7. 硬错误为空才把四项相加；否则 `valid=false`、总分为 0，但仍返回维度和规则明细。
8. 带版本 revision、规则 hash、UTC 计算时间构造响应，调用 `persist()` 写库后返回。写库失败不会继续返回成功响应。

> ⚠ 这条 GET 会更新 `schedule_versions.score`，不是只读缓存命中。每次都会重新统计。
>
> ⚠ 规则使用冻结 hash，但 `loadModel()` 读取的是当前主数据，不是输入快照；修改周课时、教师上限或科目分类后，历史版本重算结果可能变化。

### `public ScoreDiffResponse diff(long organizationId, long versionId, long againstId)`

相同版本先抛 400；然后依次调用两次 `score()`，所以会分别更新两个版本的评分快照。把对照版本维度按 `key` 建 Map，遍历当前维度，以“当前已得分 − 对照已得分”形成差值；对照缺少该 key 时按 0 分处理。总分差同样是当前减对照。

方法没有拒绝不同规则 hash，也没有要求两个版本属于同一年级；调用方需结合两个响应的规则指纹理解可比性。方法未声明事务，第二次评分失败不代表第一次写入会一起回滚。

### `private List<String> hardViolations(ScheduleVersion version, Model model)`

1. 调 `validator.validate(version)`；捕获其 `BusinessException`，将 detail 收集为一条错误后继续。该校验器遇到第一个问题就抛出，因此这里不能声称一次列出全部撞课与越界。
2. 按 `classId:subjectId` 统计条目数。
3. 遍历当前组织全部班级及匹配年级的课程方案，逐项比较应排与实排，`weeklyHours=null` 按 0 处理；同时记录合法组合。
4. 实际出现但不在方案中的班级/科目组合，另外报错。
5. 按教师累计周课时，超过非空 `maxWeeklyHours` 则报错。

> ⚠ 班级循环没有按版本年级缩小范围；多年度/多年级数据下，其他班级也可能被报“实际 0 节”。这是当前实现范围，不能描述为只校验本版本年级。
>
> ⚠ `VersionValidator` 的源码特别要求用 `LinkedHashMap` 保持首个教师冲突的遍历顺序；注释记载，曾实测 Python 与 Java 因 HashMap 顺序不同而返回不同冲突。评分捕获的也是这一首条错误，不能忽略该顺序约定。

### `private Measure measure(ConstraintRule rule, Model model)`

按类型分派给下面七种统计；可选 id 用 `optionalLong()` 读取。`teacher_unavailable` 将规则中从 1 开始的 day/period 各减 1，其他课表坐标已从 0 开始。

> ⚠ 源码明确要求新增 handler 时同步定义评分复核口径。未知类型返回 `Measure(1, 1, ...)`，满足度为 0：软规则扣分，硬规则让版本无效；不会静默按满分处理。

### 各统计方法（按源码顺序）

| 方法签名 | 数据流及计数口径 |
|---|---|
| `subjectMaxPerDay(Model model, Long subjectId, int max)` | 可选过滤科目 → 按班级/科目/星期计数 → 累加 `max(0, n-max)`；机会数是过滤后课时数 |
| `subjectNoConsecutive(Model model, Long subjectId)` | 把班级/科目/日/节次放入 Set → 对每个位置查下一节是否存在；三节连排算两处相邻，机会数仍是课时数，不是相邻槽位数 |
| `teacherMaxDaily(Model model, Long teacherId, int max)` | 可选过滤教师 → 按教师/日分组 → 累加超出日上限的课时；机会数是目标教师的课时数 |
| `teacherUnavailable(Model model, long teacherId, int day, int period)` | 数目标教师在指定坐标的全部命中；机会固定 1，撞课数据可能使违规大于 1，取整函数会把满足度下限钳为 0 |
| `subjectAvoidLast(Model model, Long subjectId)` | 每条目标课程都算一次机会；通过班级→年级当天作息取最后节次，位置相等才违规，不能用全校统一末节 |
| `subjectMorning(Model model, Long subjectId, int morningPeriods)` | 可选科目过滤，位置 `>= morningPeriods` 违规；没有 subject_id 时统计全部课程，不自动筛选主科 |
| `teacherGaps(Model model, Long teacherId)` | 按教师/日收集节次 → Set 去重 → 取首尾 → `尾-首+1-不同节次数`；0/1 个节次没有空档，早于首课和晚于末课不计。机会数为课时数，空档可能比机会还多 |
| `distribution(Model model)` | 按班级/科目再按日计数 → 每天 `max(0,n-1)` 相加；机会数为总课时。这是同日集中程度，不是五天方差 |
| `mainSubjectMorning(Model model)` | 从当前科目表取忽略大小写的 `category=major` → 只数这些课 → `periodIndex>=4` 算下午；与规则参数可配的 `subjectMorning()` 是两种口径 |

例：某教师当天上第 1、4 节，内部索引为 0、3，空档是 2、机会是 2，空档维度得 0 分；这不是按全天空闲比例扣分。

### 数据装配与辅助方法

| 方法签名 | 按代码顺序解释 |
|---|---|
| `loadModel(long organizationId, ScheduleVersion version)` | 条目同时按组织和版本筛选；班级、年级、教师、科目、年级课程方案均按组织取当前表。前四类用 `indexed()` 转 id Map，方案保留 List |
| `requireVersion(long organizationId, long versionId)` | 按 id 与组织查一条；无结果统一 404“课表版本不存在”，不暴露跨租户版本 |
| `persist(long organizationId, long versionId, ScoreResponse response)` | Jackson 序列化整个响应，再 `updateScore()`；捕获 JSON 异常并转 `IllegalStateException`。这里没有显式比较 revision，也没有检查更新行数，不能宣称并发快照一定对应写入时最新 revision |
| `dimension(String key, String label, int max, int earned, long actual, long opportunities, String explanation)` | 填充维度，扣分直接为 `max-earned` |
| `points(int max, Measure measure)` | 将违规、机会交给 `ScoreMath.dimensionPoints()` |
| `percent(long violations, long opportunities)` | 将计数交给 `ScoreMath.satisfactionPercent()` |
| `optionalLong(RuleParams params, String name)` | 有字段才 `requireLong()`，无字段返回 null；null 表示不做目标 id 过滤 |
| `periods(Model model, long classId, int day)` | 查班级→年级；缺年级、缺作息、day 越界都返回 0，否则用 `DAY_KEYS` 映射工作日并取节数，缺键同样为 0 |
| `<T> Map<Long,T> indexed(List<T> items, Function<T,Long> id)` | 按 id 排序后放入 `LinkedHashMap`，后续遍历有稳定顺序 |

私有 record `Measure` 保存违规数、机会数、解释；`Model` 保存条目与五类主数据。它们是本次计算的数据容器，不是数据库实体。

## 9.4 `ScoreMath` —— 先取整百分比，再折算分数

**源码**：[ScoreMath.java](../backend-java/orbit-scheduling/src/main/java/com/orbit/scheduling/score/ScoreMath.java)

**谁调它**：`ScoreService` 的分数与百分比辅助方法。类不可实例化，方法为包级静态方法。

| 方法签名 | 精确口径 |
|---|---|
| `satisfactionPercent(long violations, long opportunities)` | 机会数 ≤0 返回 100；否则 `round(100 × max(0,机会-违规)/机会)` |
| `dimensionPoints(int maxPoints, long violations, long opportunities)` | 先调用上项得到整数百分比，再 `round(maxPoints × 百分比/100)` |
| `weightedSoftPoints(long weightedPercentSum, long totalWeight)` | 总权重为 0 返回 50；否则 `round(50 × 加权百分比和/(100 × 总权重))` |

> ⚠ 第 7 册的比例是概览：实现会先取整百分比，再折算维度分数。绕过第一次取整直接计算，在边界上可能相差 1 分。空机会记满分也会发生在没有目标课程时，不能单凭高分推断课程完整。

## 9.5 `ScoreResponse` / `ScoreDiffResponse` —— 分数与差值契约

**源码**：[ScoreResponse.java](../backend-java/orbit-scheduling/src/main/java/com/orbit/scheduling/score/ScoreResponse.java)、[ScoreDiffResponse.java](../backend-java/orbit-scheduling/src/main/java/com/orbit/scheduling/score/ScoreDiffResponse.java)

**谁使用**：service 创建，controller 返回；完整评分还会序列化到版本 score 字段。这两个 record 没有额外业务方法。

| record | 字段及用途 |
|---|---|
| `ScoreResponse` | `versionId/revision/ruleSetHash` 标识本次口径；`valid/totalScore` 表示有效性与最终分；`hardViolations` 是硬错误；`dimensions` 是四维统计；`ruleBreakdown` 是逐规则统计；`computedAt` 是计算时间 |
| `Dimension` | `key/label` 标识维度；`maxPoints/earnedPoints` 是分值；`actual` 是该维度原始违规量，`opportunities` 是可评机会；`deduction` 为扣分；`explanation` 为文字口径 |
| `RuleMetric` | `ruleType/hardness/weight` 标识规则参数之外的基本信息；`violations/opportunities/satisfactionPercent` 是统计；`explanation` 是结论。这里没有规则 id |
| `ScoreDiffResponse` | `current/against` 是两份完整评分；`totalDelta` 为当前减对照；`dimensions` 是按 key 对齐后的差值 |
| `DimensionDelta` | `key/label/currentPoints/againstPoints/delta`；正差表示当前该维度分数较高 |

## 9.6 两个 `LegacyJacksonConfig` —— 显式提供 Jackson 2

**源码**：[scheduling 配置](../backend-java/orbit-scheduling/src/main/java/com/orbit/scheduling/config/LegacyJacksonConfig.java)、[assistant 配置](../backend-java/orbit-assistant/src/main/java/com/orbit/assistant/config/LegacyJacksonConfig.java)

**谁调它**：Spring 配置扫描调用 `ObjectMapper legacyObjectMapper()` 注册 Bean；使用方包括持久化、助手审计与协议解析代码。

方法创建 `com.fasterxml.jackson.databind.ObjectMapper`，设置 `PropertyNamingStrategies.SNAKE_CASE` 后返回。例如 `ruleSetHash` 序列化为 `rule_set_hash`。

两份配置各属于独立服务。源码注释指出 Boot 4 Web 层默认使用 Jackson 3，而已有持久化仍用 Jackson 2；不能把这一个 Bean 描述为替换了所有 Web JSON 配置。

> ⚠ 方法只设置命名策略，没有在此注册 Java 时间模块。评分响应含 `LocalDateTime computedAt`，因此不能仅凭这段配置保证持久化序列化成功；需要运行时验证实际注入对象是否有额外模块。本次只补文档，没有改配置或声称这个路径已通过运行验收。

## 9.8 助手五个 record —— 输入、会话、消息、动作与额度

**源码目录**：[model](../backend-java/orbit-assistant/src/main/java/com/orbit/assistant/model)

**谁使用**：`AssistantController` 接收请求，`AssistantService` 与 `AssistantRepository` 装配响应。以下 record 均无自定义方法；Java 自动提供构造器、访问器及值语义方法。

| 类 | 全部字段与用途 |
|---|---|
| `ChatRequest` | `conversationId` 可空，用于新建或续接；`message` 带 `@NotBlank(message="Field required")`；`tool` 为显式工具名；`arguments` 为参数 Map。后两者没有在 record 上做工具白名单校验，实际限制由路由与 service 执行 |
| `ConversationResponse` | `id/title/createdAt/updatedAt`：会话标识、标题及两个时间 |
| `MessageResponse` | `id/conversationId/turnIndex` 定位消息和轮次；`role/content` 表示角色和正文；`tokenCount` 为记录的 token 数；`createdAt` 为时间 |
| `ActionResponse` | `id/conversationId/turnIndex/toolName` 定位动作；`arguments/result/proposal` 分别保存输入、结果与草案 Map；`status` 为状态；`expectedRevision/finalRevision` 是可空修订号；`errorDetail` 为失败信息；`createdAt/decidedAt` 为创建与决定时间 |
| `UsageResponse` | `usedTokens/dailyBudget/remainingTokens` 是额度数字；`llmEnabled/mode` 是模型开关与模式。record 只承载结果，不负责计费和预算扣减 |

> ⚠ Map 与 String 字段不是 Java 枚举约束；这些 DTO 的类型声明本身不能保证动作状态合法、参数完整或草案可以执行。应继续读第 8 册的路由、工具白名单和确认事务。
