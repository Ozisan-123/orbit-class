# 代码导读 6a：前端基础、API、类型与课表组件

> 本册覆盖前端入口、应用壳、HTTP 适配层、共享类型、`Timetable` 与全局样式。
> 各业务页面见 6b。

## 0. 前端数据流

```text
main.tsx
  → App：恢复登录态
  → Shell：菜单、路由、改密
  → pages/*：持有页面状态
  → api/index.ts：附 token、处理 401、调用后端
  → Java gateway / academic / scheduling

课表页面
  → ScheduleEntry[] + periodsPerDay[]
  → Timetable：转成“行=节次、列=星期”的表格
  → onMove(entryId, day, period)
  → 页面决定是直接换课还是先预览
```

前端没有全局业务 store。除登录用户外，列表、表单和弹窗状态都留在页面组件内；`zustand` 是为后续助手会话预留的。

## 2. `App.tsx`：登录态与应用壳

**源码**：[App.tsx](../frontend/src/App.tsx)

### `Shell`

**输入**：当前 `user`、退出回调、用户更新回调。

**职责**：左侧导航、顶部用户菜单、业务路由与修改密码弹窗。

#### 菜单构造

固定包含数据、固定时段、规则、排课、课表；系统管理仅对非 operator 展示。规则页虽在菜单数组中显示给所有角色，但路由层仍会把 operator 重定向到 `/data`；后端管理员校验是最终防线。

⚠ 菜单隐藏不是权限控制。真正权限必须在 Java Controller/Security 中执行。

#### `changePassword()`

1. `form.validateFields()` 执行必填、最小长度和确认密码一致性校验。
2. 调 `api.changePassword`。
3. 成功后提示、关弹窗、清表单。
4. 本地把 `must_change_password` 改为 false，避免再弹一次。

若用户必须改初始密码，弹窗不可关闭、不可点遮罩取消；这是前端体验约束，后端仍负责验证旧密码和新密码规则。

#### 路由

| 路径 | 页面 | 特殊条件 |
|---|---|---|
| `/data` | `DataManagement` | 所有登录用户 |
| `/schedule/config` | `ScheduleConfig` | 所有登录用户 |
| `/schedule/rules` | `RuleManagement` | operator 被重定向 |
| `/schedule/generate` | `ScheduleGenerate` | 所有登录用户 |
| `/schedule/view` | `ScheduleView` | 传入当前用户 |
| `/system` | `SystemManagement` | operator 被重定向 |

根路径和未知路径都回到 `/data`，不会留下空白页。

### `App`

#### 状态

- `user`：null 表示未登录。
- `loading`：应用启动时是否正在用本地 token 恢复会话。

#### `logout()`

删除 `orbit_token` 并把 user 置空。它不请求服务端，因为当前 JWT 是无状态 token。

#### 启动 `useEffect`

1. 监听全局 `orbit:unauthorized` 事件。
2. localStorage 有 token 时请求 `/auth/me` 验证并恢复用户。
3. 失败则清 token；无 token 则直接结束 loading。
4. 组件卸载时移除监听器。

这个事件由 Axios 响应拦截器发出，使任何页面遇到 401 都能统一回到登录页。

#### 三态渲染

`loading` 显示验证动画；无 user 显示 Login；有 user 才创建 BrowserRouter 和 Shell。路由树因此不会在身份未确定时短暂展示受保护页面。

## 3. `api/index.ts`：所有 HTTP 契约的前端入口

**源码**：[api/index.ts](../frontend/src/api/index.ts)

### Axios 实例与请求拦截器

实例 `baseURL='/api'`，开发期交给 Vite 代理，生产期交给 gateway 同源转发。每次请求读取 localStorage token，存在时加 `Authorization: Bearer ...`。

### 响应拦截器

非登录请求收到 401 时删除 token 并广播 `orbit:unauthorized`。登录接口的 401 被排除，因为“密码错误”应留在登录页面显示，而不是再触发一次全局登出。

### `listAll<T>(url, params)`

它把 Java 的 `{items,total}` 临时还原成旧页面需要的数组：

1. 强制 `size=200`。
2. 请求 `Page<T>`。
3. 若 total 大于本页条数，控制台明确告警。
4. 返回 `data.items`。

⚠ 这只是迁移适配，不是真正服务端分页；超过 200 条仍会截断。任务列表已走真正分页，其余主数据页需要逐页改造。

### 认证

| 函数 | 请求 | 说明 |
|---|---|---|
| `login` | `POST /auth/login` | 用户名密码换 token/用户信息 |
| `getMe` | `GET /auth/me` | 验证 token 并恢复用户 |
| `changePassword` | `POST /auth/change-password` | 字段转换为 snake_case |

### 账号与组织

`getUsers`、`getOrganizations` 经 `listAll`；`createUser`、`updateUser`、`createOrganization` 将页面对象原样传给后端。

⚠ 这些写函数仍使用 `any`，编译器无法发现字段拼错；扩展页面时应补请求 DTO，而不是继续传播 `any`。

### 系统运维

- `getStorageStatus` 返回对象，不走分页。
- `clearGeneratedSchedules` 固定带确认串 `CLEAR_SCHEDULES`。
- `compactDatabase` 发起数据库整理。

### 教务主数据

| 资源 | 读 | 写 |
|---|---|---|
| 年级 | `getGrades` | create/update/delete |
| 班级 | `getClasses(gradeId?)` | create/update/delete |
| 科目 | `getSubjects` | create/delete |
| 年级课时 | `getGradeSubjects(gradeId?)` | create/bulk/delete |
| 教师 | `getTeachers` | create/update/delete |

筛选参数只有有值时才发送，避免把 `undefined` 误当成查询条件。

`updateGradeSubjectsBulk` 返回裸数组：它是写操作后的完整状态，不是列表查询契约，不能套 `listAll`。

### 任教分配

- `getAssignments` 可按 teacher/class 筛选。
- `createAssignment` 建单条分配。
- `autoAssignTeachers` 支持覆盖旧分配和限定科目。
- `setTeacherClasses` 返回该教师更新后的裸数组。
- `deleteAssignment` 删单条。

### 固定课

`getGradeFixedSlots` 可按年级筛选；新增、删除分别映射 POST/DELETE。

### 排课与版本

| 函数 | 作用 |
|---|---|
| `generateSchedule` | 新建排课任务 |
| `getScheduleStatus` | 取组织级简化状态 |
| `getScheduleVersions` | 版本列表，当前仍经 `listAll` |
| `updateScheduleVersion` | 改名/描述，body 应带 expected_revision |
| `copyScheduleVersion` | 复制为新草稿 |
| `publishScheduleVersion` | 发布并归档旧发布版 |
| `getScheduleAudit` | 版本审计，当前经 `listAll` |
| `swapScheduleEntry` | 执行拖动/交换 |

`getClassSchedule`、`getTeacherSchedule`、`getGradeSchedule` 明确保留裸数组，因为一张课表天然有上限且组件需要完整矩阵。

### `exportSchedule(versionId?)`

1. 以 blob 请求 xlsx。
2. 创建临时 object URL。
3. 构造隐藏下载链接并触发 click。
4. 立即 revoke URL 释放浏览器资源。

文件名目前固定为 `课表.xlsx`，没有解析后端 Content-Disposition。

### 规则系统

| 函数 | 关键点 |
|---|---|
| `getRuleTypes` | schema 驱动动态表单 |
| `getRules` | 数量天然有限，后端返回裸数组 |
| `getCurrentRuleSet` | 版本号、hash、规则数 |
| create/update | 保存完整规则数据 |
| `setRuleEnabled` | 带 expected_revision |
| `deleteRule` | revision 放查询参数 |
| `trialRule` | 只做编译试算，不落库 |
| getRuleVersions/detail | 审计规则集历史 |
| `getDiagnosis` | `deep=true` 才做昂贵冲突集分析 |

### 任务队列

`getJobs` 是当前唯一真正使用服务端分页的前端列表；`getJob` 取详情；`getJobEvents` 取事件时间线；`retryJob` 只适用于 failed/cancelled；`cancelJob` 对 pending 立即终结，对 running 只设置取消请求。

## 4. `types/index.ts`：前后端 JSON 的静态镜像

**源码**：[types/index.ts](../frontend/src/types/index.ts)

### 基础与分页

`Page<T>` 固定 `{items,total}`。Grade、Class、Subject、Teacher、Assignment、GradeSubject 与后端响应逐字段对应；可选的 `*_name` 是后端补出的展示字段。

### 课表

- `ScheduleEntry` 是一格课程，星期和节次均从 0 开始。
- `ScheduleStatus.status` 目前是 string，没有收窄成状态联合类型。
- `ScheduleVersion.status` 收窄为 draft/published/archived。
- `ScheduleAudit.action` 罗列生成、编辑、复制、移动、交换、跨班交换、发布。

⚠ 新增审计动作时要同步扩展联合类型，否则后端正常响应会在前端类型层不成立。

### 用户与运维

`User.role` 限定 platform_admin/admin/operator；`StorageStatus.counts` 用动态表名到数量的 Map，Redis 状态允许内存字段缺失。

### 规则类型

`RuleParamSpec` 是 solver-core schema 的镜像；`RuleType` 描述一种能力；`Rule` 描述一条实例；`RuleVersion` 的 rules 仅详情返回。

⚠ `enum_values` 在接口中始终是数组，即便为空也不能省略，动态表单依赖它判断枚举控件。

### 诊断

`Diagnosis.kind` 刻意区分 INFEASIBLE 与 UNKNOWN：前者是已证明无解，后者可能只是超时。页面不能把两者都提示成“请修改数据”。

### 任务

`ScheduleJob` 包括排队位置、attempt、租约过期、取消标志、worker、结果和时间；`JobEvent` 是不可变的状态变化时间线。

## 5. `Timetable.tsx`：把条目数组变成课表矩阵

**源码**：[Timetable.tsx](../frontend/src/components/Timetable.tsx)

### Props

| 属性 | 作用 |
|---|---|
| `entries` | 全部课程格 |
| `periodsPerDay` | 周一到周五每天节数 |
| `editable` | 开启拖拽与点选 |
| `moving` | 请求进行中，暂时禁交互 |
| `showTeacher` | 是否显示教师 |
| `colorize` | 是否按科目着色 |
| `compact` | 缩短格子高度 |
| `onMove` | 把动作交还页面处理 |

组件只表达“用户想把哪一条移到哪里”，不知道后端是直接执行还是先预览，因而可被多个页面复用。

### 三组交互状态

- `draggedId`：HTML5 拖拽中的课程。
- `selectedId`：触屏/键盘不方便拖拽时，第一次点击选中的课程。
- `overCell`：当前悬停目标格，用于高亮。
- `draggedRef`：阻止一次拖拽结束紧接着触发 click。

### `maxPeriods`

取每天节数最大值并至少为 1，确保没有作息数据时表格仍能渲染表头和一行，不会传空数组导致 `Math.max` 为负无穷。

### 列定义

第一列显示“第 N 节”。之后按五个工作日生成列，每个 render 从行对象读取对应 `ScheduleEntry`。

`canDrop` 同时要求 editable、非 moving、目标节次在该天实际节数内；不同年级每天节数可以不同，不能只看最大行数。

### 点击移动

第一次点有课程的格子记录 selectedId；第二次点目标格后清选择，若不是原格则调用 `onMove`。无源课程或点回原位不会发请求。

### 拖拽移动

`dragStart` 同时把 id 写入 state 和 `dataTransfer`，前者服务当前 React 树，后者让浏览器拖拽协议也有数据。drop 优先用 state，取不到时再读 dataTransfer；随后清理所有交互状态并调用 `onMove`。

### 课程卡片

科目 id 对颜色数量取模，保证同科目颜色稳定。editable 时显示拖动图标和操作提示；`showTeacher=false` 可用于教师本人课表，避免重复显示姓名。

### `dataSource`

按节次生成行，再为五天各找一条 day/period 匹配记录。复杂度约为“格子数 × entries 数”；学校周课表只有几十至几百项，足够简单可靠。

⚠ 若未来展示全校上万条记录，应先把 entries 建成 Map，不能继续每格 `.find()`。

## 7. 修改前端基础层时的检查表

- API 路径是否仍以 `/api` 开头并由代理/网关分流？
- 401 是否只触发一次全局退出，登录失败是否仍能留在登录页显示？
- 返回裸数组的课表接口是否误套了 `listAll`？
- 新增写接口是否有明确请求类型，还是又用了 `any`？
- 后端 snake_case 字段变化是否同步到 types？
- 新增状态或审计动作是否扩展联合类型？
- Timetable 的目标格是否尊重每天不同节数？
- 拖拽期间是否用 moving 防止重复提交？
