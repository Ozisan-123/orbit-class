# 代码导读 6b：前端 7 个业务页面

> 本册按用户旅程解释七个页面。共享入口、API、类型和 `Timetable` 见
> [6a：前端基础与课表组件](代码导读-6a-前端基础与课表组件.md)。

## 0. 页面地图

```text
Login
  → DataManagement：年级/班级/科目/教师/任教
  → ScheduleConfig：年级固定课
  → RuleManagement：可配置约束与诊断
  → ScheduleGenerate：生成任务、排队、重试、草稿预览
  → ScheduleView：查看、调课、复制、发布、审计、导出
  → SystemManagement：账号、组织、存储运维
```

页面遵循同一模式：组件内 state → `useEffect` 首次加载 → API 调用 → antd 展示。没有 Redux，也没有跨页面业务 store。

## 1. `Login.tsx`

**源码**：[Login.tsx](../frontend/src/pages/Login.tsx)

**上游**：`App` 在没有已验证用户时渲染。

**下游**：`api.login`；成功后调用父组件传入的 `onLogin`。

### 状态

`loading` 防止重复提交，`error` 保存服务端错误文案。

### `submit({username,password})`

1. 开启 loading 并清旧错误。
2. 调登录接口。
3. 把 `access_token` 写入 localStorage。
4. 把返回的 user 交给 App，App 随即切到 Shell。
5. 失败优先显示后端 `detail`，无响应时显示网络兜底文案。
6. finally 恢复按钮。

表单默认用户名是 admin，仅用于本地演示便利；密码不预填。

## 2. `DataManagement.tsx`

**源码**：[DataManagement.tsx](../frontend/src/pages/DataManagement.tsx)

这是前端最大的数据录入页，把年级、班级、科目周课时、教师与任教关系放在四个 Tab 中。

### `loadAll()`

并行加载六份基础数据，任一失败显示统一错误并结束 loading。页面很多派生关系依赖完整集合，因此这里选择一次装齐。

⚠ 当前这些接口通过 `listAll(size=200)` 拉取；大型学校超过上限时页面会不完整，是待改的真实服务端分页遗留。

### `weeklyHours`

用 `subject_id:grade_id` 作为 Map key，将年级课时从数组变成 O(1) 查询，供科目表和教师负载计算复用。

### `onGradeOk()`

验证表单，把五个 `p_Mon...p_Fri` 字段重组为 `periods_per_day` JSON，创建后清弹窗并全量刷新。

### `onClassOk()`

直接提交班级名和 grade_id。关联有效性由后端校验。

### `onSubjectOk()`

把动态年级输入重组为 `weekly_hours_by_grade`，一次创建科目及各年级课时。0 明确表示该年级不开设。

### `openHoursEditor(subject)` / `saveHours()`

打开时从 Map 回填每个年级当前课时；保存时提交完整 items 数组到 bulk 接口。历史课表版本不会被改，变化只影响下一次排课。

### `onTeacherOk()`

1. 按换行拆教师姓名，去空白与空行。
2. `Promise.all` 批量逐个创建教师。
3. 默认对该科目执行覆盖式自动分配。
4. 根据 `unassigned` 给出教师不足提示。

⚠ 多个创建请求不是一个前端事务：中途某个失败时，已成功的教师不会自动撤销。真正批量原子性需要后端批量接口。

### `openAssignmentEditor(teacher)` / `onAssignmentOk()`

打开时回填该教师已有 class_ids；保存时调用“设置教师全部班级”接口。后端负责转交已由他人负责的班级并校验课时上限。

### `autoAssignAll()`

确认后以 `replace_existing=false` 补齐缺口，保留人工分配。未分配项用可滚动警告弹窗逐条展示。

### `assignmentsForTeacher` / `assignedHoursForTeacher`

前者筛某教师分配；后者沿“分配 → 班级 → 年级 → 该科年级周课时”计算当前负载，并与教师上限比较。

### `eligibleClassesForTeacher(teacher)`

只显示该教师科目在对应年级周课时大于 0 的班级，避免把教师分到未开设这门课的年级。

### 动态表格与表单

- 科目表按当前年级动态生成列。
- `gradeHourFields` 复用“每年级一个 InputNumber”的表单结构。
- 教师表实时显示负载、任教班级和超额红色提示。
- 删除均有 Popconfirm，但最终外键/业务保护在后端。

## 3. `ScheduleConfig.tsx`

**源码**：[ScheduleConfig.tsx](../frontend/src/pages/ScheduleConfig.tsx)

用于配置“某年级所有班同一时段都上同一科目”的固定课。

### `load()`

并行读年级、班级、任教和全部固定课；首次选择第一个年级。错误不会静默吞掉。

### 派生数据

- `gradeClasses`：当前年级班级。
- `gradeSlots`：当前年级固定时段。
- `slotAt(day,period)`：查某格配置。

### `availableSubjects`

一门课可被设为全年级固定课，必须同时满足：

1. 每个班恰有一名该科教师。
2. 各班教师互不相同。

否则同一时段会让一个教师同时去多个班。页面提前过滤，后端仍会重复校验。

### `openCell(day,period)`

保存当前格坐标，若已有固定课则回填 subject_id，再开弹窗。

### `saveCell()`

提交 grade/subject/day/period。成功后关闭、提示并重新加载，确保采用后端真实状态。

### `deleteCurrent()`

根据当前坐标找到 slot id 后删除；没有现有 slot 时直接返回。

### 课表矩阵

每天节数来自年级 `periods_per_day`。用最大节数生成行；某天超出自身节数的格子显示灰块且不可点击。已固定格显示科目、图钉和覆盖班级数。

## 4. `RuleManagement.tsx`

**源码**：[RuleManagement.tsx](../frontend/src/pages/RuleManagement.tsx)

页面核心不是写死十种规则表单，而是消费后端 schema 动态渲染。

### `load()`

并行获取规则实例、可配置类型、全部类型、当前规则集与版本历史。mandatory 类型单独用于“系统规则始终生效”说明。

### `openCreate()` / `openEdit(rule)`

新建时清状态并默认 soft/weight=1/enabled=true。编辑时锁定 rule_type，把动态 params 展开回填到同一 Form。

### `collectParams(type)`

只收集 schema 声明过且非空的字段，防止切换类型后把旧字段残留提交给新规则。

### `currentType()` / `buildPayload()`

前者按 selectedType 找 schema；后者组合 rule_type、动态 params、hardness、weight、description，供试算和创建共享。

### `doTrial()`

没有类型先提示；有类型则提交草稿。结果展示 handler 的人话解释、能否编译、问题、变量增量和模型是否变化。

### `save()`

1. 先跑 antd 表单校验。
2. 编辑时提交当前 revision，创建时提交 buildPayload。
3. 成功关闭并重载。
4. `errorFields` 表示前端表单错误，antd 已展示，不再弹重复消息。

### `toggle(rule,enabled)` / `remove(rule)`

二者都带 rule.revision。开关失败仍强制 reload，把乐观 UI 拉回服务器真值；删除成功重载列表与当前版本。

### `runDiagnosis(deep)`

浅诊断毫秒级检查数据；深诊断会多次求解以定位冲突规则。UI 用同一个 diagnosing 标志禁止并发点击。

### `renderParamField(spec)`

- INT/LONG → InputNumber，带 min/max。
- BOOL → Switch，必须指定 `valuePropName="checked"`。
- ENUM → Select，选项来自 enum_values。
- 其它 → Input。

⚠ 新增规则类型无需改页面，但新增一种参数“类型”必须扩展这个 switch。

### 诊断展示

OK/UNKNOWN/INFEASIBLE 分别使用成功/警告/错误；静态发现和冲突规则分组展示。UNKNOWN 只表示超时未证明，不能诱导用户修改数据。

### 版本历史

规则集按 hash 去重，改回旧状态时“当前版本”可能是编号较小的历史版本，页面专门解释这一点，避免用户误判。

## 5. `ScheduleGenerate.tsx`

**源码**：[ScheduleGenerate.tsx](../frontend/src/pages/ScheduleGenerate.tsx)

它同时展示组织级简化状态、P3 任务队列和最新草稿预览。

### 状态分层

- `status` 回答“组织现在是否在排课”。
- `jobs/jobsTotal/jobsPage` 回答排队、attempt、worker、错误等细节。
- `previewVersion/entries` 是完成后的草稿预览。
- `pollingRef` 保存定时器 id，避免重复轮询。

### `loadJobs(page)`

以 10 条每页请求真正服务端分页。任务列表失败只提示，不中止正在运行的排课主流程。

### 初始加载

并行读班级与年级，默认选第一个班；同时加载任务首页。

### `stopPolling()` / `startPolling()`

开始前先清旧定时器。每秒刷新简化状态与当前任务页；done/failed/cancelled/idle 都停止 loading，done 额外加载最新草稿。请求异常也停轮询，避免后台永久报错。

⚠ 状态请求和任务列表解决不同问题，两者都刷新才看得见排队位置与接管。

### `loadLatestDraft(classId)`

加载版本列表，优先第一个 draft，否则取列表首项；有班级时再拉对应课表。

### `generate()`

先清旧预览并显示“正在启动”，再创建任务、刷新任务列表、开始轮询。启动失败把页面状态置 failed 并恢复按钮。

### `movePreviewCourse(...)`

预览区当前仍直接调用 swap，带草稿 revision。冲突时重新加载最新草稿，避免界面继续持有过期 revision。

### `cancelJob(job)` / `retryJob(job)`

pending 取消立即生效；running 只是请求 worker 在下一检查点停止。重试后回任务首页，以便看到新排队位置。

### `openEvents(job)`

打开 Modal 并加载领单、心跳、接管、失败、取消事件。事件记录用于解释“为什么任务又跑了一次”。

### 任务列

- lease_expired 显示“等待接管”。
- pending 显示前面任务数。
- running 显示进度条。
- done 显示课时数与版本。
- failed/cancelled 才出现重试。

## 6. `ScheduleView.tsx`

**源码**：[ScheduleView.tsx](../frontend/src/pages/ScheduleView.tsx)

这是课表工作区：版本管理、单班/双班、教师、年级、拖拽、发布、导出和审计集中在这里。

### 初始状态与选择

并行加载年级、班级、教师和版本。默认版本优先 draft，其次 published，再其次第一条；默认班级、对照同年级班、教师和年级也在此设置。

### `reloadVersions(preferredId?)`

重载后尽量保留 preferred/current id；不存在才按 draft → published → first 回退。用于乐观锁失败后的状态恢复。

### `loadClass()` / `loadCompareClass()`

根据 selectedVersionId 加载主班和对照班。对照班为空时主动清 entries，避免旧班课表残留。

### 多组 `useEffect`

- 主/对照选择变化时重载课表。
- 主班变化时确保对照班仍属于同年级且不是同一班。
- 只有切到教师/年级 Tab 时才请求对应大视图。
- 版本不是 draft 时自动关闭编辑模式。

### `replaceVersion(updated)`

局部替换版本列表里的对象，使新 revision 立即进入后续写请求。

### `onMove(entryId,day,period,targetClassId)`

带 selectedVersion.revision 调 swap。成功替换版本并重载两班；失败显示 detail，同时重载版本和课表，处理别人已修改导致的 409。

⚠ 当前是“拖后直接提交”；方案 P5 要改为“预览 → 确认”。

### `openMeta()` / `saveMeta()`

回填和保存方案名、备注；保存请求带 expected_revision。成功用返回的新对象替换本地版本。

### `copyVersion()`

任何版本都可复制为草稿；成功后优先选中新草稿并打开编辑模式。

### `publishVersion()`

确认框说明发布会复验冲突并归档旧正式版。只有非 operator 且当前是 draft 才显示按钮；后端仍执行权限校验。

### `showAudit()`

打开 Drawer 并加载版本级审计。Timeline 用 action 映射成人话，dayjs 统一格式化时间。

### `gradeGroups`

把年级大数组按 class_id 分组，每班渲染一个 Timetable。

### 三个视图

- 班级：单班或同年级双班对照，双班用于跨班协同换时。
- 教师：按教师看课表，目前每天固定传 8 节作为显示上限。
- 年级：所有班按响应式网格展开。

### 显示选项

科目配色、显示教师和紧凑模式统一打包成 `timetableOptions`，传给每个 Timetable，保证三个视图行为一致。

## 7. `SystemManagement.tsx`

**源码**：[SystemManagement.tsx](../frontend/src/pages/SystemManagement.tsx)

### 加载

所有管理员加载本组织 users 与 storage；仅 platform_admin 加载 organizations。

### `addUser()`

验证并创建本校账号，成功提示首次登录改密、清表单并重载。

### `addOrganization()`

平台管理员一次创建工作空间与首位管理员，成功后刷新组织列表。

### 账号表操作

- Switch 调 updateUser 改启用状态。
- 重置密码用 Modal.confirm 动态插入密码框，onOk 再从 DOM 取值并检查 8 位。

⚠ 这里绕过了 antd Form，校验体验与其它弹窗不一致；重构时应改成受控表单。

### 存储页

展示数据库类型、位置、大小、各表记录数和 Redis 状态。整理空间与清空课表都有二次确认；清空只删生成数据，不删基础配置。

### 权限展示

工作空间管理 Tab 只给 platform_admin。普通 admin 新建账号时也不能选择 platform_admin，避免界面越权提权。

## 8. 页面层已知遗留

- 多数主数据表仍是 `size=200` 拉全量后的浏览器分页。
- `DataManagement`、`RuleManagement`、`ScheduleView` 文件过大，方案要求随功能扩展拆组件。
- 写请求普遍使用 `any`，缺请求 DTO。
- 页面测试为 0；方案要求 Vitest + RTL，并至少一条 Playwright 主链路。
- ScheduleView 与草稿预览仍直接 swap，尚无干跑确认。
- 助手抽屉、空闲查询和评分卡尚未实现。
- 教师课表显示上限硬编码 8 节，未从教师所涉年级作息推导。

## 9. 修改页面时的检查表

- API 失败后是否把 loading/saving/moving 放回 false？
- 乐观锁失败后是否重拉版本与 revision？
- operator 隐藏按钮之外，后端是否仍有最终权限保护？
- 异步请求返回时，当前选择是否可能已经变化并导致旧数据覆盖新状态？
- 表格是否误以为拿到了全部数据，而实际被 200 条截断？
- “证明无解”和“超时未证明”是否仍用不同文案？
- 拖拽换课是否经过预览确认，而不是直接写入？
