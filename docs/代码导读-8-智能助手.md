# 代码导读 8：智能助手（P4 + P5）

> 助手启动类、五个请求/响应 record、Jackson 兼容配置及管理员初始化逐方法说明，见[第 9 册：后端补遗](代码导读-9-后端补遗.md)。

> 本册覆盖 `orbit-assistant` 与前端助手抽屉。它不是一个能绕过业务接口的“万能机器人”，
> 而是一个受工具白名单、租户权限、人工确认和审计记录共同约束的教务操作入口。

## 1. 最终能力

助手现在有两种运行模式：

| 模式 | 启用条件 | 能力 | 故障策略 |
|---|---|---|---|
| 本地模式 | 未配置 `LLM_API_KEY` | 用确定性中文规则识别常用查询与草案命令 | 完全离线、可测试 |
| 模型模式 | 配置 `LLM_API_KEY` | 用 OpenAI Responses 兼容接口理解更自然的表达与对象名称 | 调用失败自动退回本地模式 |

模型只负责把一句话转换成 `{tool, arguments}`。教师是否空闲、课表内容、诊断结论等事实，
仍然来自 academic / scheduling 的现有接口；模型不能自己编答案。

支持的只读工具：

- `check_teacher_availability`：教师某一时段是否空闲；
- `check_class_availability`：班级某一时段是否空闲；
- `find_free_slots`：教师某天的空闲节次；
- `get_timetable`：按班级、教师或年级查询课表；
- `get_job_status`：查询排课任务；
- `explain_diagnosis`：读取普通或深度诊断；
- `score_timetable`：读取课表质量评分；
- `check_config`：分页拉全并检查教务主数据。

支持的变更草案：

- `propose_rule`：先调用规则试算，再展示规则草案；
- `propose_swap`：先调用换课预览，再展示影响范围；
- `propose_reschedule`：展示当前配置并警告将新建排课任务。

任何草案都不会自动执行。只有用户点击“确认执行”后，后端才会调用正式接口；取消、成功、失败
都会落入动作审计表。

## 2. 一次对话怎么流动

```text
AssistantDrawer
  → POST /api/assistant/chat（JWT + SSE）
  → AssistantService 创建/续接会话并记录用户消息
  → LlmIntentRouter 或 IntentRouter 只选择白名单工具
  → ToolGateway 携带原 JWT 调 academic / scheduling
  → 只读：记录结果并流式回答
  → 写意图：试算/预览，保存 proposed 动作
  → 前端 ProposalCard 等待用户确认
  → confirm：事务锁定动作，调用正式接口，记录 confirmed/failed
```

SSE 事件依次可能是：

| 事件 | 含义 |
|---|---|
| `meta` | 会话 ID 与轮次 |
| `tool_call` | 即将调用的工具与参数 |
| `tool_result` | 只读工具的真实返回 |
| `proposal` | 等待确认的草案 |
| `token` | 分段显示的助手文字 |
| `done` | 本轮正常结束 |
| `error` | 参数不足或业务系统拒绝 |

## 3. 后端逐类说明

### `AssistantController`

它只负责 HTTP 契约，共 8 个入口：聊天、会话列表、消息列表、删除会话、动作列表、确认、取消、额度。
`chat()` 返回 120 秒的 `SseEmitter`；确认接口必须继续转发原始 `Authorization`，否则下游无法做
相同租户和用户鉴权。

### `AssistantService`

- `stream()`：按组织限制并发 SSE 数量，实际工作放进 Java 21 虚拟线程；
- `runTurn()`：记录消息、路由意图、检查工具白名单与预算、调用工具、保存动作、发送 SSE；
- `route()`：显式工具优先；有密钥且额度未耗尽时走模型；模型故障走本地解析；
- `confirm()` / `reject()`：事务内 `SELECT ... FOR UPDATE`，保证同一个草案不能被重复确认；
- `usage()`：返回组织当天已用、预算、剩余额度及当前模式。

额度耗尽后不会再调用外部模型，也拒绝创建新的变更草案；已有只读能力仍可用。

### `LlmIntentRouter`

直接使用 JDK `HttpClient` 调 OpenAI Responses 兼容端点。`HttpClient` 延迟创建，因此未配置模型时
不会建立任何外部连接。系统提示词规定：

1. 只能返回白名单工具；
2. 不得编造 ID、版本、修订号；
3. 信息不足必须返回追问；
4. 变更只能选 `propose_*`；
5. 星期和节次在进入 API 时转换成从 0 开始的索引。

响应解析同时兼容顶层 `output_text` 与 Responses 原始 `output[].content[]` 形状，解析后还会再次检查
工具白名单。模型返回一个不存在的工具会被直接拒绝。

### `IntentRouter`

这是离线降级路由。它用明确的关键词和数字位置解析评分、诊断、任务、课表、空闲、换课与规则。
`requireAfter()` 找不到必需数字时立即追问，不会用默认 ID 猜测。

### `ToolGateway`

这是助手唯一接触业务系统的地方：

- 只走已有 HTTP 接口，不直接修改 academic / scheduling 的表；
- 原样转发用户 JWT，让下游继续执行租户隔离；
- 名称参数先通过 academic 分页接口精确解析；找不到或重名就提示改用 ID；
- `check_config` 按每页 200 条循环拉取，不会只检查第一页；
- 规则先 `/api/rules/trial`，换课先 `/swap/preview`；
- `apply()` 只接受三种已经保存过的草案类型。

### `AssistantRepository`

使用 `JdbcTemplate` 明确保存四类记录：

| 表 | 用途 |
|---|---|
| `assistant_conversations` | 用户自己的会话标题与时间 |
| `assistant_messages` | 每轮 user / assistant 消息及估算 token |
| `assistant_actions` | 工具参数、结果、草案、确认状态、修订号、错误 |
| `rule_generation_attempts` | 规则生成文本、生成结果、最终是否接受 |

所有查询都带 `organization_id + user_id`；删除会话依靠外键级联清理消息、动作与规则尝试。

### 安全类

- `AssistantJwtFilter`：校验 JWT，并确认用户仍存在且启用；
- `AssistantPrincipal`：向控制器传递用户与组织；
- `AssistantSecurityConfig`：无状态会话，除健康检查外全部要求登录。

## 4. 前端逐组件说明

- `assistantStore.ts`：保存抽屉、当前会话、消息、动作、流式文字、实时工具和额度；
- `AssistantDrawer.tsx`：悬浮入口、会话列表、示例问题、输入区、额度条和 SSE 生命周期；
- `MessageList.tsx`：按角色显示消息，并把同一轮动作挂到助手消息下；
- `ToolCallTrace.tsx`：折叠展示工具名、参数、真实结果和执行状态；
- `ProposalCard.tsx`：展示预览 JSON，提供确认/取消按钮并显示失败原因；
- `api/index.ts`：用 `fetch + ReadableStream` 解析 SSE，其他接口继续使用统一 Axios 实例。

## 5. 配置与启动

默认不需要模型密钥，直接运行项目就是本地模式：

```powershell
.\start-dev.cmd
```

如需模型模式，在根目录 `.env` 增加：

```dotenv
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://api.openai.com
LLM_MODEL=gpt-4o-mini
ASSISTANT_DAILY_TOKEN_BUDGET=200000
```

`LLM_BASE_URL` 也可填写兼容服务的根地址、`.../v1` 或完整 `.../v1/responses`。

启动后登录 Web，在右下角点击机器人按钮。顶部标签会显示“本地模式”或“模型模式”。

## 6. 手工验收顺序

建议使用已有真实 ID，依次测试：

1. `检查当前排课配置`：出现 `check_config` 工具轨迹；
2. `评分版本 1`：返回分数数据，内容可在工具结果中核对；
3. `教师 1 在版本 1 周三第 2 节是否空闲`：检查 day=2、period=1；
4. `查看任务 1` 与 `深度诊断版本 1`；
5. `提议规则 教师 1 周三第 2 节不可用，硬规则 权重 10`：只出现草案，数据库规则尚未变化；
6. 取消草案：状态变为“已取消”；
7. 再生成草案并确认：正式接口成功后状态变为“已执行”；
8. `提议换课 版本 1 课程 1 到班级 1 周三第 2 节 修订 0`：先看到冲突/影响预览，再决定是否确认；
9. 刷新页面：会话、工具轨迹、草案状态仍存在；
10. 用另一个账号登录：不能读取前一个账号的会话。

自动验证命令：

```powershell
cd backend-java
mvn test

cd ..\frontend
npm run lint
npm run build
```

原稿记录的验证基线（本次文档补全未重跑）：后端 87 个测试全部通过；前端 lint 与生产构建通过。构建仅有一个“大包超过 500 KB”的
性能提示，不影响功能，后续可用路由懒加载拆包。

## 7. 目前边界

- 模型不直接生成最终业务答案，它只做意图路由；这是为了让所有事实可追溯；
- token 数目前按消息字符估算，用于租户预算保护，不等同于供应商账单；
- 当前名称解析要求精确同名；重名时必须改用 ID；
- SSE 是逐段显示服务端已经形成的回答，不是把供应商原始流直接透传；
- 智能助手不会发布课表，重新排课也只创建任务。

## 8. 真实启动验收发现的 Boot 4 注意点

- Spring Cloud Gateway 5 的路由键是 `spring.cloud.gateway.server.webflux.routes`；沿用旧键会表现为
  “网关健康、所有业务路径却 404”；
- Boot 4 将 `RestClient.Builder` 自动配置拆到了 `spring-boot-restclient`，仅有 Web starter 不够；
- Web 层默认 Jackson 3，而 MyBatis JSON 类型与现有持久化代码仍使用 Jackson 2，因此两个对象映射器
  必须明确分工，RestClient 返回先读取成标准 `Map/List/Object`；
- SSE 会发生 Servlet `ASYNC` 二次派发，首次请求校验 JWT 后要允许同一异步请求完成，否则响应已经
  返回 200 后还会被安全链拦截并提前断开；
- 共享非空 schema 中，每个服务的 Flyway history 表都必须使用 `baseline-on-migrate: true` 且
  `baseline-version: 0`，否则新服务第一次加入时会拒绝启动或静默跳过 V1；
- Java 版启动时先确保至少有一个组织；全库没有用户才创建平台管理员。已有用户时不覆盖账号或密码，但在全库没有平台管理员时，可能把第一个组织中 id 最小的 admin 提升为 platform_admin，详见第 9 册。
